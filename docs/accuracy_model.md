# Analytical accuracy model for quantized DOT and GEMV

This document defines the mathematical predictions generated by
`tools/build_accuracy_model.py`. Equations use plain ASCII so they remain
readable in a terminal.

## 1. Scope and assumptions

The source distributions are:

```text
U01: X ~ U(0, 1)
N01: X ~ N(0, 1)
```

Every matrix and vector entry is independently generated from the selected
distribution. Both operands currently use the same storage format and are
encoded independently. There is no rescaling.

The storage model analyzes:

```text
source value       X
encoded/decoded    Q(X)
quantization error e = Q(X) - X
```

DOT and GEMV storage predictions initially assume exact multiplication and
addition after decoding. FP64 kernel arithmetic is treated separately by a
roundoff bound. Scalar, packed-2, and packed-4 access have the same storage
model because packing does not change `Q(X)`.

The following assumptions are important:

- round-to-nearest-even has zero-probability ties for continuous sources;
- CUDA FP8 E4M3 and E5M2 constructors are modeled as saturating to their
  largest finite magnitude, matching the `__NV_SATFINITE` conversion used by
  the implemented CUDA wrapper;
- custom finite E1 formats saturate, while custom E2/E3 formats produce
  infinity after finite-range overflow;
- FP16, BF16, FP32, E11M4, and E11M20 use IEEE-style non-finite overflow;
- FP64 storage is the identity map for FP64-generated inputs.

## 2. A storage format is a quantizer

Let the finite decoded values of a format be `q_i`. Under round-to-nearest,
the decision cell for an interior value is bounded by the midpoints to its
neighbors:

```text
C_i = [(q_(i-1) + q_i)/2, (q_i + q_(i+1))/2)
```

For a deterministic codec:

```text
Q(x) = q_i when x is in C_i
```

Saturating formats extend the two outer cells to negative and positive
infinity. Infinity-producing formats stop the finite cells at the overflow
threshold. The probability outside those cells is reported separately.

For formats with at most 14 fraction bits, the implementation enumerates all
finite decoded values and integrates every cell. Denser formats use the
high-resolution cell approximation described in Section 5; the report labels
the method for every format.

## 3. Source interval moments

For any cell `[a,b)`, define:

```text
I0(a,b) = integral_a^b p(x) dx
I1(a,b) = integral_a^b x p(x) dx
I2(a,b) = integral_a^b x^2 p(x) dx
```

For `U(0,1)`, first clip the interval to `[lo,hi] = [a,b] intersect [0,1]`:

```text
I0 = hi - lo
I1 = (hi^2 - lo^2) / 2
I2 = (hi^3 - lo^3) / 3
```

For `N(0,1)`, with standard normal CDF `Phi` and density `phi`:

```text
I0 = Phi(b) - Phi(a)
I1 = phi(a) - phi(b)
I2 = I0 + a*phi(a) - b*phi(b)
```

The implementation evaluates tail probabilities through the survival function
to avoid subtracting two floating-point values close to one.

## 4. Scalar coupling moments

The cell integrals produce the moments of the coupled pair `(X,Q(X))`:

```text
E[X]       = sum_i I1(C_i)
E[X^2]     = sum_i I2(C_i)
E[Q]       = sum_i q_i I0(C_i)
E[Q^2]     = sum_i q_i^2 I0(C_i)
E[X Q]     = sum_i q_i I1(C_i)
```

For numerically stable kernel propagation, the implementation also calculates
moments of the signed error directly:

```text
m_x  = E[X]
m_e  = E[e]
x2   = E[X^2]
xe   = E[X e]
e2   = E[e^2]
```

The principal scalar metrics are:

```text
scalar bias = m_e
scalar MSE  = e2
scalar RMSE = sqrt(e2)
```

`P(Q(X)=0)`, overflow probability, and saturation probability are also
reported. When a format maps overflow to infinity, finite moments are
conditioned on the scalar encoding remaining finite. Unconditional MSE is then
infinite; the finite-conditioned value and failure probability are both shown.

## 5. High-resolution approximation

Enumerating `2^23` or `2^30` fraction cells is impractical. Within one binade,
the representable spacing is constant:

```text
step(e) = 2^(e - fraction_bits)
```

For a locally smooth source density and round-to-nearest:

```text
cell MSE approximately step(e)^2 / 12
```

The dense-format scalar MSE is calculated by integrating the probability mass
in every binade:

```text
D approximately sum_e P(X in binade e) * step(e)^2 / 12
```

The subnormal interval uses its constant subnormal spacing. Saturated tails are
integrated exactly. In the non-saturated interior, the centroid approximation
uses:

```text
E[e]   approximately 0
E[X e] approximately -D
E[e^2] approximately D
```

This approximation becomes extremely accurate as the number of fraction bits
increases. It is not presented as exact. CPU simulation will be the next check
for these curves.

## 6. Exact DOT storage bias and MSE

For one product, use independent copies `(A,e_a)` and `(B,e_b)` of `(X,e)`:

```text
Q(A)Q(B) - AB
    = A*e_b + B*e_a + e_a*e_b
```

The mean product error is:

```text
mu_term = 2*m_x*m_e + m_e^2
```

Its second moment is:

```text
second_term =
    2*x2*e2
    + e2^2
    + 2*xe^2
    + 4*xe*e2
```

This error-moment form avoids subtracting nearly equal values such as
`E[Q^2]^2` and `E[X^2]^2` for high-precision formats.

For independent coordinates, define:

```text
var_term = second_term - mu_term^2
```

For a DOT of length `N`:

```text
dot bias = N * mu_term

dot MSE = N*var_term + N^2*mu_term^2

dot RMSE = sqrt(dot MSE)
```

The `N^2` term is why even a small systematic encoding bias can eventually
dominate random quantization noise.

The equivalent formula in terms of `(X,Q)` moments is:

```text
mu_term = E[Q]^2 - E[X]^2

second_term = E[Q^2]^2 + E[X^2]^2 - 2*E[X Q]^2
```

## 7. Absolute-error distribution approximation

The exact bias and MSE above do not determine all percentiles. For sufficiently
large `N`, the central limit theorem motivates:

```text
dot error approximately Normal(dot_bias, N*var_term)
```

The report uses the folded-normal distribution to calculate:

```text
approximate mean absolute error
approximate p95 absolute error
```

These values are labeled as approximations. They can be poor for small `N`,
rare saturation events, or strongly discrete low-bit errors.

## 8. Relative and normalized error

Let:

```text
Z = sum_i A_i B_i
S = sum_i abs(A_i B_i)
```

The source reference second moment is exact:

```text
E[Z^2] = N*x2^2 + N*(N-1)*m_x^4
```

The report uses the stable ratio-of-RMS metric:

```text
relative RMS = sqrt(E[error^2]) / sqrt(E[Z^2])
```

This is not `E[abs(error/Z)]`. For a zero-mean source with density near
`Z=0`, that pointwise expectation can diverge and is not a useful analytical
summary.

The expected absolute-product sum is:

```text
E[S] = N * E[abs(X)]^2
```

The report's normalized-error scale is:

```text
normalized RMSE proxy = sqrt(E[error^2]) / E[S]
```

The measured metric will instead use `abs(error)/S` for every sample. The
analytical ratio is a scale prediction, not the expectation of that random
ratio.

For `U(0,1)`, every product is nonnegative, so the actual condition number
`S/abs(Z)` is exactly one. For `N(0,1)`, the report estimates a typical
condition number using a normal approximation to `Z`; measured condition
percentiles will come from simulation.

## 9. GEMV with fixed M = 1024

For row `j` of an `M` by `N` matrix:

```text
y_j = sum_i A[j,i] x[i]
```

Each row has the same marginal storage-error formulas as a length-`N` DOT.
Therefore:

```text
row bias = dot bias(N)
row MSE  = dot MSE(N)

E[||error||_2^2] = M * row MSE

RMS L2 error = sqrt(M * row MSE)
```

Likewise:

```text
E[||y||_2^2] = M * E[Z^2]

relative L2 RMS =
    sqrt(E[||error||_2^2] / E[||y||_2^2])
```

The relative L2 RMS is independent of `M`; changing `M` increases the number
of sampled rows and scales the absolute L2 error by `sqrt(M)`. Rows share the
same vector `x`, so row errors are not fully independent. This does not affect
the expected squared L2 norm, but it does matter for exact maximum-error and
percentile distributions.

## 10. Overflow and saturation probabilities

Let `p_finite` be the probability that one encoded scalar remains finite and
`p_sat` the probability that it lies in the saturation tail.

For DOT, two length-`N` inputs are encoded:

```text
P(any nonfinite input) = 1 - p_finite^(2N)

P(any saturated input) = 1 - (1-p_sat)^(2N)
```

For GEMV, the complete matrix and shared vector contain `M*N + N` values:

```text
P(any nonfinite input) = 1 - p_finite^(M*N + N)

P(any saturated input) = 1 - (1-p_sat)^(M*N + N)
```

For comparison with the fraction of non-finite output rows, the marginal
per-row probability instead uses the `N` matrix values in that row and the `N`
shared-vector values:

```text
P(nonfinite inputs for one row) = 1 - p_finite^(2N)

P(saturated inputs for one row) = 1 - (1-p_sat)^(2N)
```

The row events are correlated because all `M` rows share the same vector.
Consequently, estimating these probabilities requires enough independently
generated vectors, not merely many output rows from one matrix/vector pair.

These are input-failure probabilities. Exact output NaN/Inf probability can be
smaller in special cases such as multiplication by zero, but should normally
be very close once any operand becomes infinite.

The implementation evaluates `1-p^K` with `log1p`/`expm1` so very small tail
probabilities remain visible.

## 11. FP64 kernel arithmetic bound

The storage model above assumes exact post-decode arithmetic. For FP64
round-to-nearest, define:

```text
u64 = 2^-53
gamma(k) = k*u64 / (1-k*u64)
```

If an FP64 FMA/reduction path introduces at most `k` rounding steps, the
standard absolute bound has the form:

```text
abs(gpu_result - storage_ref)
    <= gamma(k) * sum_i abs(Q(A_i)Q(B_i))
```

The normalized kernel-error bound is therefore approximately `gamma(k)`.
The report estimates `k` from:

- the maximum per-thread FMA count;
- packed-lane combination depth;
- an eight-level 256-thread block reduction;
- for DOT, the second-stage partial reduction.

This is a conservative structural model, not an exact prediction. CUB may use
a different instruction ordering, and actual rounding depends on the data.
Only comparison with `gpu_result - storage_ref` validates kernel arithmetic.

## 12. Storage, kernel, and total error

For every future GPU test, retain three values:

```text
source_ref  = accurate result from original FP64 source values
storage_ref = accurate result from decoded storage values
gpu_result  = CUDA kernel result
```

Then:

```text
storage error = storage_ref - source_ref
kernel error  = gpu_result - storage_ref
total error   = gpu_result - source_ref
```

The analytical DOT/GEMV moment model predicts storage error. Section 11 gives
only a kernel-error bound. Total measured error must be obtained from the GPU
or a bit-accurate emulation of its complete reduction order.

## 13. Interpretation of generated values

| Quantity | Status |
|---|---|
| Scalar cell moments, fraction bits <= 14 | Numerical evaluation of exact cell integrals |
| Scalar moments, denser formats | High-resolution approximation |
| DOT bias and MSE from scalar moments | Exact propagation of supplied moments |
| GEMV row MSE and expected squared L2 norm | Exact propagation of supplied moments |
| Mean/p95 absolute error | Folded-normal approximation |
| Relative RMS | Exact ratio of second moments, not mean pointwise relative error |
| Normalized RMSE | Ratio-to-expected-normalizer approximation |
| Typical N01 condition number | Normal approximation |
| Overflow/saturation input probability | Exact from scalar tail probability and independence |
| FP64 arithmetic error | Conservative structural bound |

The planned validation order is analytical prediction, CPU Monte Carlo, and
finally GPU measurement. Disagreement should be diagnosed at the earliest
layer rather than absorbed into a single total-error number.
