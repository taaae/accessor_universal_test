# E1M6 strategy decision

E1M6 uses the repository's finite E1 policy: exponent value one is finite, not
Inf/NaN. As a result, the seven magnitude bits form one signed fixed-point
integer `K`, and the exact magnitude is `K * 2^-5`.

Implemented strategy core:

- generic codec control;
- branchy direct FP64 high-word construction;
- masked direct FP64 high-word construction;
- exact FP32-bit construction followed by FP32-to-FP64;
- fixed-point integer-to-FP64 followed by multiplication by `2^-5`;
- complete 256-entry FP64-high-word LUT from global or shared memory;
- subnormal/fixed-grid high-word LUT support for later placement comparisons;
- 65,536-entry pair LUT in global/L2 for x4/x8 packet decoding;
- byte-permute extraction and bank-swizzled/duplicated shared-LUT variants;
- x1, x2, x4, and x8 aligned packet loads.

The full table is only 1 KiB. Shared staging is therefore credible in both DOT
and GEMV, although GEMV still pays the prologue once per row block. The primary
unknown for H200 is whether random shared lookup is cheaper than integer-to-FP64
conversion. Both remain P0 candidates.

Local validation exhausts all 256 codes and requires exact FP64 bits for the
branchy, masked, FP32-intermediate, and fixed-point paths.
