# FP32 E8M23 strategy decision

FP32 is the native numerical-conversion control. Every source value maps
exactly to FP64 through `cvt.f64.f32`, and source subnormals are negligible for
the benchmark distributions. A direct decoder can instead construct FP64's two
words, using CLZ only for true FP32 subnormals.

Implemented candidates:

- generic/native scalar FP32-to-FP64 conversion;
- float2/float4 packet loads followed by lane-wise conversion, plus exploratory
  x8 as two float4 packets;
- branchy exact FP64-word construction;
- masked/predicated exact FP64-word construction;
- 512-entry, 2 KiB sign/exponent prefix helper through global or shared memory;
- x1/x2/x4 and exploratory x8 packet widths.

Complete and subnormal LUTs are excluded at 32 GiB and 64 MiB. The prefix
helper is a secondary candidate because exponent rebias is already cheap.
Validation uses 200,000 deterministic bit patterns plus boundary classes and
compares NaNs by class.
