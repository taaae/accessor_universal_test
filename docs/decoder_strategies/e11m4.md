# E11M4 strategy decision

E11M4 stores the top 16 bits of an FP64 value: sign, the complete 11-bit FP64
exponent, and four leading fraction bits. Exact decoding is only:

```cpp
__hiloint2double(int(uint32_t(raw) << 16), 0)
```

Implemented candidates:

- generic prefix-codec control;
- direct prefix-word insertion at x1/x2/x4/x8;
- complete 65,536-entry high-word LUT through global/L2 as a negative control.

No FP32 intermediate is exact over E11M4's range. No zero, subnormal, Inf, or
NaN branch is needed because their FP64 encodings are already present in the
stored prefix. The likely winner is direct insertion; packet width determines
whether wider loads help or merely increase live FP64 registers. Local
validation exhausts all 65,536 encodings bit-for-bit.
