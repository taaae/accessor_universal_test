# FP16 E5M10 strategy decision

FP16 has native scalar and `half2` CUDA conversion support. Every decoded value
is exactly representable in FP32, but FP64 arithmetic still requires one
FP32-to-FP64 conversion per lane. Source subnormals are below 0.01% for the
chosen distributions.

Implemented candidates:

- generic native-codec control;
- scalar half-to-FP64 C++ conversion;
- scalar half-to-FP32-to-FP64 conversion;
- native `half2`-to-`float2` conversion, composed for x4/x8;
- branchy and masked direct FP64 high-word construction;
- exact FP32-bit construction followed by FP64 conversion;
- complete 65,536-entry high-word LUT through global/L2;
- 1,024-entry, 4 KiB subnormal LUT through global or shared memory;
- x1/x2/x4/x8 aligned packet loads.

The direct-word route avoids `cvt.f64.f32`; the native route may compensate by
decoding two halves efficiently. Exhaustive local validation covers all FP16
bit patterns, with NaNs compared by class.
