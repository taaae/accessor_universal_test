IEEE, LNS summary

full_lut_shared

a[i] semantic does not work as it is.

H200 allows 227 KB shared memory per block, so the table fits up to 15 bits (128 KB) — same for FP32 and FP64, one 32-bit word per code.

FP64 tables store 32-bit entries holding the double’s high word; the low word is a literal zero.

__global__ void kernel(...) {
  extern __shared__ uint32_t table[];

  for (i = threadIdx.x; i < table_size; i += blockDim.x)
    table[i] = global_table[i];

  __syncthreads();  // block-collective, so it cannot live inside operator[]

  out[i] = table[a[i]] * x[i];
}

Solution:

template <typename Acc>
__global__ void kernel(Acc acc, const double *x, double *out, std::size_t n) {
  auto a = acc.stage();                     // barrier inside; all threads
  const auto i = blockIdx.x * blockDim.x + threadIdx.x;
  if (i < n) out[i] = a[i] * x[i];
}

E1 — unreliable

The test data sits almost entirely in E1’s subnormal range.

uniform(0,1)normal(0,1)
share below smallest normal (2)100%95.4%
What this breaks

E1 has one exponent bit, so the bias is 0: subnormals span [0, 2) and the single normal binade spans [2, 4), both in steps of 21−M. The code space is one uniform ramp, which is what lets e1_integer decode it branchlessly as magnitude × 21−M — the exponent bit is just the high bit of the magnitude field. E1 is an integer format in the same sense E0 is.

e1_integer measures 1.20–1.64x faster than direct_branchy, but that margin is bought by the table above. direct_branchy renormalizes subnormals — leading-bit search, variable shift, exponent reassembly — and with 95–100% of values below the smallest normal it takes that path on essentially every value. On data inside [2, 4) it would take the cheap path instead and the gap would shrink. Neither distribution puts meaningful mass there, so this run cannot say by how much.

e1_integer’s own times are identical across the two distributions to four digits — it is genuinely data-independent. The sensitivity lives entirely in its competitor.

E1M0 is separately degenerate: 1 sign bit, 1 exponent bit, no mantissa, so it encodes only ±0 and ±inf and no finite nonzero values. e1_integer does not apply to it.

FP64   S EEEEEEEEEEE MMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMMM

Dense vs padded

Dense packs values back to back and reads them out of a 32-bit word pair:

// one value, any width
bit   = index * Bits;
pair  = words[bit / 32] | (words[bit / 32 + 1] << 32);   // two loads
value = (pair >> (bit % 32)) & mask;                     // shift + mask

Padded gives every value its own container and reads it directly:

// one value, container is uint8_t / uint16_t / uint32_t
value = data[index] & mask;                              // one load

The container is the smallest of 1, 2 or 4 bytes that holds the format:

format bitscontainerbytes/valuewasted
2–8uint8_t10–75%
9–16uint16_t20–44%
17–32uint32_t40–47%

At small widths the kernel is limited by per-value memory instructions, not by bytes. Spending extra bandwidth to halve the load count is a good trade.

For GEMV padded always wins. For DOT dense wins only where the container would waste a lot: 9 and 10 bits unpacked, marginally at 12, and 17–28 bits once packing is available — and every one of those wide wins is a shift decoder.

Dense vs padded

Dense packs values back to back and reads them out of a 32-bit word pair:

// one value, any width
bit   = index * Bits;
pair  = words[bit / 32] | (words[bit / 32 + 1] << 32);   // two loads
value = (pair >> (bit % 32)) & mask;                     // shift + mask

Padded gives every value its own container and reads it directly:

// one value, container is uint8_t / uint16_t / uint32_t
value = data[index] & mask;                              // one load

The container is the smallest of 1, 2 or 4 bytes that holds the format:

format bitscontainerbytes/valuewasted
2–8uint8_t10–75%
9–16uint16_t20–44%
17–32uint32_t40–47%

At small widths the kernel is limited by per-value memory instructions, not by bytes. Spending extra bandwidth to halve the load count is a good trade.

For GEMV padded always wins. For DOT dense wins only where the container would waste a lot: 9 and 10 bits unpacked, marginally at 12, and 17–28 bits once packing is available — and every one of those wide wins is a shift decoder.
